# 🚀 Implementation Plan

This document outlines a phased, LLM-friendly implementation strategy for the Flashcard Learning System. Each phase is designed to be modular, isolated, and incremental — ensuring that code generated by LLMs can be constructed from scratch where possible.

Each phase includes **prompt-based development instructions** with **step-by-step goals** and **checkable outputs**. Prompts have been further refined into sub-phases for improved granularity.

---

## 🗂️ Phase 1: Project Setup & Foundations

**🎯 Objective**: Establish a clean, modular project structure and shared environment configuration.

**📝 Description**: Create backend and frontend scaffolds with Docker setup, environment variables, and folder structure.

### 🧩 Sub-Phase 1.1: Git and Project Initialization
> Create a Git repository with `main` and `dev` branches. Initialize a `backend/` folder for FastAPI and a `frontend/` folder for React. Add a `.gitignore` and basic README files for each.

✔️ Output:
- Git repository initialized
- `backend/README.md`, `frontend/README.md`
- `.gitignore` with Python and Node settings

### 🧩 Sub-Phase 1.2: Backend + Docker Setup
> Generate a `backend/` project with FastAPI and Docker. Add `Dockerfile`, `docker-compose.yml`, and load environment variables from a `.env` file.

✔️ Output:
- `main.py` with FastAPI instance
- Dockerfile builds and runs backend
- `docker-compose` includes PostgreSQL container

### 🧩 Sub-Phase 1.3: Frontend + TailwindCSS + DaisyUI
> Initialize a React project (e.g., Vite). Add TailwindCSS and DaisyUI. Create a home screen and navigation shell.

✔️ Output:
- Tailwind working in dev server
- Default layout with responsive header/footer

### 🧩 Sub-Phase 1.4: Folder Structure and Scaffolding
> Create the backend module folders: `auth`, `datasets`, `sessions`, `gamification`, `spaced`, `dashboard`, with each containing `models.py`, `routes.py`, `schemas.py`, and `__init__.py`.

✔️ Output:
- Folder and module structure matches specification

## 🔐 Phase 2: Authentication (Module: `auth/`)

**🎯 Objective**: Secure user access using JWTs and role control.

**📝 Description**: Add registration, login, user storage, and access guard logic.

### 🧩 Sub-Phase 2.1: User & Role Models
> Create SQLAlchemy models for `User` and `UserRole` with UUID keys. Include password hash.

✔️ Output:
- `users` and `user_roles` tables
- Alembic migration created

### 🧩 Sub-Phase 2.2: Auth Routes
> Add `/register` and `/login` endpoints. Use Pydantic schemas and validate user input. Generate JWT.

✔️ Output:
- Users can register and log in
- JWT issued on login

### 🧩 Sub-Phase 2.3: JWT Guard Dependency
> Add `get_current_user()` dependency to restrict access. Add admin-only variant.

✔️ Output:
- Secured sample route using `Depends`

## 📚 Phase 3: Dataset Management (Module: `datasets/`)

**🎯 Objective**: Allow admin to import and list datasets.

### 🧩 Sub-Phase 3.1: Dataset Models
> Create `Dataset`, `Element`, and `Field` models with foreign keys. Use UUIDs.

✔️ Output:
- Models and migrations added

### 🧩 Sub-Phase 3.2: Upload Endpoint
> Add `POST /datasets/upload` that accepts JSON body or file upload. Normalize and insert data.

✔️ Output:
- Dataset can be uploaded
- Admin check applied

### 🧩 Sub-Phase 3.3: Dataset Listing
> Add `GET /datasets/` to return names and IDs.

✔️ Output:
- Frontend can show dataset list

## 🧠 Phase 4: Learning Sessions (Module: `sessions/`)

**🎯 Objective**: Build flashcard review and tracking engine.

### 🧩 Sub-Phase 4.1: Session Models
> Add `UserLearningSet`, `UserElementReview` tables. Link to `users` and `elements`.

✔️ Output:
- Migration created

### 🧩 Sub-Phase 4.2: Start Session
> Add `POST /session/start` to select a dataset and assign 10 elements to user.

✔️ Output:
- Elements assigned and persisted

### 🧩 Sub-Phase 4.3: Show Flashcard
> Add `GET /session/next` to return a question with distractors.

✔️ Output:
- Valid question with 4 choices

### 🧩 Sub-Phase 4.4: Submit Answer
> Add `POST /session/answer` to track correctness and success streak.

✔️ Output:
- Review record updated
- Element marked mastered if streak met

## ⏳ Phase 5: Spaced Repetition (Module: `spaced/`)

**🎯 Objective**: Schedule next reviews using timestamps.

### 🧩 Sub-Phase 5.1: Extend Review Model
> Add `interval_days`, `next_due`, and `last_reviewed_at` to review table.

✔️ Output:
- Columns added with default logic

### 🧩 Sub-Phase 5.2: Update Logic
> Increase interval after correct answer; reset on failure. Store timestamp.

✔️ Output:
- Review behavior is adaptive

### 🧩 Sub-Phase 5.3: Due Filtering
> `GET /session/next` returns due items before new ones.

✔️ Output:
- Sorting honors due logic

## 🔁 DevOps: CI/CD, Config & Monitoring

**📌 Objective**: Automate deployment, separate environments, and track errors.

### 🔧 CI/CD Pipeline Setup
- Use GitHub Actions or GitLab CI
- Include steps for:
  - Run backend + frontend tests
  - Build Docker images
  - Push to registry
  - Deploy to VPS/staging via SSH or artifact delivery

### 🧪 Environment-Specific Configurations
- Use `.env.development`, `.env.production`, etc.
- Load based on runtime flag or container environment variable
- Add logging level, debug toggles, API base URLs per env

### 📈 Monitoring & Logging
- Integrate `loguru` or `structlog` for structured FastAPI logs
- Enable access logs and error logs in production
- Optional: use Sentry or similar for error tracking
- Monitor container health with Docker/Compose or Prometheus + Grafana
